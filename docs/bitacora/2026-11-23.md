## Architecture at HEAD

1. `execute_guest_evm_bytecode` delegates to `execute_guest_evm_bytecode_with_initial_stack`. That route calls `compile_evm_bytecode(bytecode)` with bytecode alone. Strict decoding yields offsets and operands. `symbolic::compile` emits occurrence-specific fragments, resolves local and publisher references and assembles one image.
2. `verified_program` checks declared transfers and calls `verify_final_image` on the actual RV64 words. Fixed layouts independently constrain guards, expected costs and targets, leaf call/return sites, publishers and sentinel JALR. Agreement with corrupted declarations is insufficient to authorize a transfer.
3. `execute_raw_program` loads the verified image into rvemu 0.0.11, writes an EBREAK witness to the reserved exit slot, initializes the guest and optionally seeds its operand stack. The host sets live `s1` to the next free slot after any seeded words. The execution budget in RV64 instructions is bounded by the installed image's word count.
4. The executor runs from `0x8000_0000` to the selected publisher, then to `EXIT_PC = 0x800f_fffc`. Both stops occur before fetching at the configured boundary. The publisher writes `s1`, exception code and gas, then terminal status, then performs the sentinel JALR. Counts distinguish executed body from executed termination.
5. `read_guest_result` validates the executor boundary, terminal status/code, original limit, agreement between live and published gas, the remaining-gas bound and zero exceptional gas. It checks `s0`, validates the range/alignment/depth of the published `s1`, checks it against live `s1` and reads the live stack. `GuestResult` exposes `gas_limit()`, `remaining_gas()` and `gas_used()`. Valid guest exceptions return a guest result. Malformed metadata, backend faults and instruction-limit exhaustion are host errors.

### Guest ABI

The 48-byte record begins at `0x8010_0000`. All six fields are aligned little-endian u64 words. The 1,024-word EVM operand stack begins at `s0 = 0x8010_1000`, with ascending 32-byte words. Each word contains four ascending little-endian 64-bit limbs, least significant first. `s1` is next free. Native `sp` is separate and preserved by guest state initialization.

| Offset | Field | Host initialization | Guest responsibility |
|---:|---|---|---|
| 0 | Status | RUNNING = 0 | Last metadata store. NORMAL = 1 or GUEST_EXCEPTION = 2 |
| 8 | Exception code | 0 | Publish 0 on normal, 1 for stack overflow, 2 for stack underflow, 3 for OOG |
| 16 | Final `s1` | EVM stack base | Publisher stores live `s1` |
| 24 | Input limit | Caller budget | Read-only |
| 32 | Live remaining | Caller budget | Debit after a funded check. Exceptional publisher clears to 0 |
| 40 | Published remaining | 0 | Explicitly publish live gas on success or 0 on exception |

A published zero is valid. The exact store, status-last ordering and executor boundary jointly establish publication. ### Static charge in the generated image

Example from the first PUSH1 fragment, with the actual emitter's cost and symbols:

```asm
    addi t1, s0, -2048
    addi t1, t1, -2048
    ld t0, 32(t1)
    addi t2, zero, 3
    bgeu t0, t2, guest_push1_0_gas_sufficient
    jal zero, out_of_gas_exit
guest_push1_0_gas_sufficient:
    sub t0, t0, t2
    sd t0, 32(t1)
```

`t1` holds the metadata base, `t0` the unsigned live gas and `t2` the positive immediate cost. Word 4 branches locally to word 6 on sufficiency, including equality. An unfunded path executes word 5, a symbolic JAL to OOG, with no debit or stack effects before exceptional settlement. A funded path debits once and then enters the original stack preflight. Charging only clobbers `t0`–`t2` and preserves `s0`, `s1`, `sp` and `ra`. The arithmetic leaves compute modular U256 arithmetic from the wrapper's pointers. The wrapper owns the charge and depth check, so the leaves keep the standalone arithmetic contract and byte fingerprints. ### Decisions to carry forward

- Keep one production compiler, one production guest execution implementation and one gas accounting contract. Live gas is memory-backed and guest-authoritative. The host initializes the budget and validates publication. It performs no per-opcode debit. There is no permanently reserved gas register, alternate metering route or budget-dependent compilation.
- Charge before stack validation and opcode effects. Settle any guest exceptional halt to zero remaining gas. Preserve earlier successful effects and leave the failing opcode's input stack intact. STOP and EOF are free. Treat `u64::MAX` as an ordinary unsigned budget.
- Maintain both declared-transfer and independent machine-code checks. Portable conformance covers termination class, exact settled remaining and gross used, and successful stacks. Ferreth additionally guarantees precedence, failure atomicity and publication integrity. Raw reference diagnostics remain separately inspectable.
- Remaining unmetered code has limited scope. `translate` can expose an isolated PUSH1 body or arithmetic leaf. Historical fragment generators and research linkers retain unmetered baselines. `Rv64Runner` measures standalone arithmetic and the legacy `ProgramRunner` uses a host-managed arithmetic stack. The static disassembler can already print GAS without admitting it to execution. Before closing ADR-002, audit callers, supported CLI invocations and public guest entry points for any unmetered production bypass.

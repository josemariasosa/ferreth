# How Ferreth links an RV64 guest

Ferreth compiles a sequence of EVM stack operations into one program for a 64-bit RISC-V processor. That program is the *guest*. Each operation contributes a block of instructions called a *fragment*. Linking gives each fragment an address and connects its jumps to the right instructions. A wrong connection can skip an operation or report success after a stack error, even when every individual instruction is valid.

At the Phase 3.2 documentation baseline, `dcc04cd`, one symbolic composer builds guests for STOP, PUSH1, POP, DUP1, ADD and SUB. The Human-Led Walk is complete. Phase 3.3 release validation remains pending. The execution results below belong to the named experiments and checkpoints. [Public compiler entry](../../crates/ferreth-compiler/src/compiler.rs) · [Human-Led Walk and evidence ledger](../../research/guest-linking/ferreth-human-led-walk.md)

## Why the 47th PUSH mattered

The original linkers patched jumps in machine code and rewrote assembly text to match. Ferreth then reassembled the text and compared the bytes. A program containing 46 copies of `PUSH1 2` compiled and ran. With 47 copies, the first fragment needed to jump +2056 bytes to report stack overflow, or +2060 with an explicit STOP. Both programs fit the guest code region. The numeric assembler operand hit a signed 12-bit parser limit during reassembly. Compilation failed before either guest ran (LF-026). [Raw probe](../../runs/phase-0/linking-probe.txt) · [Phase 0 reproduction and reference outputs](../../research/guest-linking/README.md)

A separate probe exposed a defect in both handwritten jump encoders (LF-027). They dropped a sign bit, turning a requested −4-byte jump into +1,048,572. The publisher jumps examined at the time went forward. This was a reproduced helper defect with no observed backward-jump failure in a production guest. [Original LF investigation and design alternatives](../../research/guest-linking/ferreth-linking-architecture.md)

Sharing patch helpers would have reduced duplication while retaining the need to keep text and bytes in agreement. The Phase 1 experiments tried *symbolic* assembly: each jump names its destination, and the assembler resolves the distance after laying out the image. The pinned assembler handled the forward and backward witnesses. It could also expand a distant conditional branch and move later labels. That observation motivated checking destinations in the **finished image**. Short guests, distant overflow exits and mixed arithmetic guests demonstrated feasibility before the public cutover. [Phase 1 experiments and limitations](../../research/guest-linking/phase-1/results/1.7-architecture-decision.md) · [Fragment interface review](../../research/guest-linking/phase-2.3-boundary-review.md)

## From bytecode to a published result

Take `60 05 60 03 01 00`: push 5, push 3, add, stop. Starting with an empty stack, the expected result is one 256-bit word containing 8.

1. **Decode and generate.** The bytecode frontend reads through the first STOP or the end of input. Each supported operation supplies symbolic RV64 source and declares its control transfers, including any required error exits. The arithmetic wrapper checks for two operands before accessing them, calls its local ADD or SUB routine, then reduces the stack depth by one. [Frontend and composer](../../crates/ferreth-compiler/src/compiler/symbolic.rs) · [Arithmetic wrapper and core evidence](../../research/guest-linking/phase-2.3c-symbolic-arithmetic.md)
2. **Compose and assemble.** A *publisher* is the short routine that records the terminal outcome for the host. The composer emits the fragments, one Normal publisher, and the Underflow or Overflow publishers requested by the fragments. It assembles the whole source once and obtains the publisher addresses from the resolved labels. Public whole-program compilation uses `compile_evm_bytecode`. The specialized PUSH1 sequence APIs described in the cutover reports were subsequently retired. [Publisher source](../../crates/ferreth-compiler/src/compiler/publisher.rs) · [Cutover evidence](../../research/guest-linking/phase-2.4-public-cutover.md) · [Subsequent API history](../../research/guest-linking/ferreth-human-led-walk.md)
3. **Check the image.** The composer bounds each declared transfer site by its owning fragment. The verifier decodes jump and branch instructions from the final words and checks their fields and destinations against the declarations. A second check uses the expected fragment layouts to enforce required transfer sites, destinations, publisher boundaries and image end. Only then does compilation return an executable artifact. [Final-image verifier](../../crates/ferreth-compiler/src/rv64/verify.rs) · [Verifier fixtures and limits](../../research/guest-linking/phase-2.1-final-image-verification.md)
4. **Execute and publish.** The host initializes the guest, optionally seeds the stack, runs to a publisher, then runs that publisher to the exit address. Register `s0` holds the stack base and `s1` the next free 32-byte slot. The publisher stores final `s1`, the exception code, and finally terminal status. It jumps to the exit independently of the local arithmetic return register. The executor stops before fetching the exit address. The host checks published metadata against live registers before reading the stack. [Accepted guest ABI](../adr/001-evm-guest-state-abi.md) · [Orchestrator](../../crates/ferreth-compiler/src/orchestrator.rs) · [Guest result validation](../../crates/ferreth-compiler/src/rv64/guest.rs)

The Human-Led Walk challenged step 3 with three consecutive PUSH1 fragments. A test redirected the first continuation past the second PUSH and changed its declaration to agree. Assembly succeeded and the declaration check passed. The fixed-layout check rejected destination `0x80000058` because the next fragment began at `0x8000002c`. This is a focused demonstration of independence. Layout identities still come from the requested operations, and control-transfer checks alone cannot establish the semantics of an ordinary load, store or arithmetic instruction. [H-WALK-003 and focused run](../../research/guest-linking/ferreth-human-led-walk.md#h-walk-003--independent-continuation-verification)

## What independent execution established

The Cancun transaction differential suite compares Ferreth against REVM 43.0.3 on directed cases and a fixed-seed corpus of 1,000 valid and 100 intentionally invalid programs. It checks termination and successful stacks. The human reviewer reported a passing suite and focused ADD/SUB integration runs on November 21. Legacy image comparisons answer a different question: whether the new path preserved selected bytes, destinations and guest behavior. [Differential tests](../../crates/ferreth-conformance/tests/rc_revm_conformance.rs) · [Walk execution ledger](../../research/guest-linking/ferreth-human-led-walk.md)

Separate experiments run one Cancun frame in pinned EELS or directly in REVM. In the walk’s EELS run the ADD example above finished with `[8]` and 91 of 100 frame gas remaining. Empty-stack DUP1 produced an exceptional halt across references, with distinct diagnostics: EELS reported `StackUnderflowError`, REVM reported `StackOverflow`, and Ferreth reported `StackUnderflow`. Preserve the original labels. Direct REVM exposes raw interpreter gas, while exceptional frame settlement is derived from the handler source. Neither transaction gas nor RV64 instruction counts measure the guest’s remaining EVM frame gas. [EELS setup and observations](../../research/eels-cancun/README.md) · [Direct REVM experiment](../../research/revm-frame/README.md) · [Conformance findings](ferreth-evm-conformance.md)

## Accepted limits and pending Phase 3 work

The supported sequence ends at the first STOP or EOF. A truncated PUSH1 immediate is zero-padded. Wider PUSH instructions can decode but are rejected by the compiler. Resource bounds also matter. The executable reservation is 1,048,572 bytes. Repeated PUSH1 and DUP1 first exceed it at 23,830 and 16,383 occurrences respectively. The earlier 20-byte POP estimate was corrected to 16 bytes (RF-016). Even so, 50,000 POPs at EOF exceed the pinned assembler’s label budget while the bytes still fit (RF-020, accepted). The investigated DUP1 relocation rejection occurs beyond the executable domain (RF-019, closed by investigation). [Sizing correction](../../research/guest-linking/phase-2.0-readiness.md) · [Boundary probes](../../research/guest-linking/phase-2.3b.1-boundary-hardening.md) · [Decoder finding H-WALK-001](../../research/guest-linking/human-led-walk-findings.md)

Phase 3.3 will reconcile those results and their revision before the maintainer's release decision.

# Phase 1.6 — Mixed symbolic guest composition

## RF-014 — Mixed symbolic guests preserve local calls and publication

Can one symbolic RV64 assembly pass compose the current supported set
(PUSH1, POP, DUP1, ADD, SUB, STOP), including repeated leaves and exceptional
paths? The production bytecode compiler is the artifact control. The
experiment runs each image through the same RV64 executor, checks it
against an explicit expected guest outcome, and samples publication.
[Experiment](../tests/mixed_symbolic_guest.rs) · [ADR-001](../../../../docs/adr/001-evm-guest-state-abi.md) · [Guest linking research](../../ferreth-linking-architecture.md)

### Source-derived contracts

| Fragment | Preconditions and exceptional destination | Success and local control flow |
|---|---|---|
| PUSH1 | Unsigned `s1 >= s0 + 32768` branches to the local overflow trampoline, which jumps to overflow (code 1). | Store the immediate as a zero-extended U256, advance `s1` by 32 and jump over the trampoline. |
| POP | Unsigned `s0 >= s1` branches to the local underflow trampoline, which jumps to underflow (code 2). | Decrement `s1` by 32 without a stack-memory access, then jump over the trampoline. |
| DUP1 | Check empty first, then capacity, each before accessing stack memory. The two local trampolines jump to underflow (code 2) and overflow (code 1) respectively. | Copy all four limbs from the top slot to the next free slot, advance `s1` by 32 and jump over both trampolines. |
| ADD | Unsigned `s1 < s0 + 64` branches to the local underflow trampoline (code 2) before operand access or a call. | Call the embedded leaf with `jal ra`. Compute top plus next modulo 2²⁵⁶, store in the lower slot, return to the `s1 -= 32` instruction, and jump over the trampoline and leaf. |
| SUB | Same depth check and underflow destination as ADD. | Same call and return sequence as ADD. Compute top minus next modulo 2²⁵⁶. |
| STOP / EOF | Normal publisher (code 0). | STOP emits a JAL to normal. EOF places normal at the last fragment's continuation. |

Both leaves take `a0 = s1 - 32` and `a1 = a2 = s1 - 64`. The
wrapper changes `s1` after the leaf returns. The guest stack remains
separate from native `sp`. The production mixed composer emits normal,
overflow and underflow publishers in that order, including unused
publishers. The symbolic fixture deliberately retains that inventory and
the same wrapper and publisher instructions.

### Composition and independent verification

Each occurrence uses its instruction ordinal in its entry, continuation,
trampoline, and, where applicable, return and leaf labels. For ADD/SUB,
the fixture takes the production `Opcode::assembly()`, filters the ELF
display directives as the production harness does, and changes only the
entry label. Each occurrence retains its own copy of the leaf. Its
`jal ra` names that copy. On return, the wrapper updates `s1` and its
continuation JAL skips the local trampoline and leaf. A continuation name
intentionally shares the next entry's PC. Explicit STOP has a single
label because reaching it terminates the decoded instruction stream.

The verifier gets entry, continuation, trampoline, core, return and
publisher addresses from the final assembler result. It scans the final
32-bit words between labels and compares every decoded transfer with the
expected sequence for that operation. It checks the B-type condition and
registers and JAL destination register, reconstructs signed immediates
from instruction bits, and adds each displacement to that word's PC.
Site and target words are checked for alignment and bounds. For calls,
the decoded call's PC plus four must equal the return label and identify
the stack decrement. The exact `jalr x0, 0(ra)` word is checked at each
leaf end. Each publisher ends in the exact `jalr x0, -4(t1)` word, with
the preceding instructions establishing `t1 = 0x80100000` from ABI `s0`.
Production bindings receive the same checks against its reassembled
display labels after verifying that reassembly matches the loaded
production bytes. Its unlabeled PUSH1 trampoline is the final word
before the next labeled boundary. All PCs come from the assembled image
or positions within its machine bytes.
[Phase 1.3 decoding and negative controls](1.3-independent-verification.md)

W has little-endian limbs `[0x1234, 0x5678, 0xffffffffffffffff, 42]`.
The capacity cases use the existing Ferreth word generator with seed 42.
Both runs of every specimen retained the 32-byte `0xa5` guard immediately
above the stack, preserved `s0` and native `sp`, and matched every live

Before each publisher, metadata still held the initialized running
record. At the first checkpoint it held the final pointer while status
was running and code was zero. Immediately before the status store it
held the final code with status still running. Immediately afterward
it held the terminal result. Exact publisher words establish the
pointer and code stores when the value stays the same. The final jump
took one instruction to the pre-fetch boundary at `0x800ffffc`, where
the production result reader validated the record against live
registers. In `808000`, for example, the sampled
`(status, code, final_s1)` tuples at `0x800000ac`, `0x800000b8`
and `0x800000bc` were `(0, 0, 0x80109000)`,
`(0, 1, 0x80109000)` and `(2, 1, 0x80109000)`.

All 17 symbolic artifacts matched current production bytes, static size,
publisher PCs and dynamic counts. Byte equality was measured after the
semantic and control-flow checks and is specific to these specimens.
The assembly uses additional zero-width names and symbolic operands in
place of the production numeric JAL operands. Appending STOP to the
repeated program added one static and one executed word and shifted all
publishers by four bytes, in both paths. These are layout and diagnostic
observations. The status, code, full stack and publication checks
establish semantic parity under the tested conditions.

The SHA-256, publisher PCs, terminal metadata, depth and counts for
`01`, `03`, `0100` and `600260030100` also matched the equivalent
artifact fields in Phase 0 (`rep_add`, `rep_sub`, `rep_add_stop`,
`rep_push_add_stop`). The two seeded arithmetic cases here use directed
carry and borrow inputs. The full-stack DUP1, empty DUP1 and empty POP
agree in outcome, pointer and dynamic counts with their Phase 0 EOF
controls. The extra STOP word shifts those publisher PCs by four bytes
without being visited on the exception path.

## Scope, regression status and exit gate

This experiment covers the supported opcode set in directed, bounded
programs on one host and executor. The current comparison uses
production RV64 artifacts and explicit expected stacks. The benchmark and
existing production suite provide their own REVM comparisons. The mixed
spike measures RV64 instructions and makes no claim about EVM frame gas.
Retaining the shared publisher inventory and one leaf copy per
arithmetic occurrence was sufficient. The verified layout relies on
occurrence-scoped names and final assembler addresses. The experiment
required no arithmetic or ABI concession. Production integration would
require the same direct-transfer, core-copy, stack, and status-last
regression checks at its public entry point.

The [new test](../tests/mixed_symbolic_guest.rs), this result, and the
[Phase 1 plan](../PLAN.md) are the Phase 1.6 diff. The existing fixtures
were reused as evidence and required no edits. The pre-existing
architecture document edit retained Git blob hash
`141d4a12172e3152716a5a92e869e05fda95c918`.

**Phase 1.6 exit gate met.** RF-014 has executable research regressions
for repeated fragments, both DUP1 exceptions, arithmetic underflow,
multi-limb carry and borrow, EOF/STOP, and ordered result publication.
Each arithmetic occurrence called and returned through its own leaf and
the documented core hashes matched. The production baseline reproduced
the four known LF-026 failures. The next action is maintainer review of
Phase 1.6.

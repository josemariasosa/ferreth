# Phase 1.5 — Long-range symbolic guest execution

## RF-013 — Symbolic PUSH1 guests execute across the LF-026 boundary

**Question.** Can the pinned assembler resolve the first overflow jump across
the legacy numeric JAL limit, and can rvemu execute both the normal paths and
the distant exception? The inputs were `6002` repeated 46 or 47 times, with
implicit EOF or one trailing `00`. All four ran from an empty stack. Both
47-PUSH layouts also ran with the Phase 0 full stack of 1,024 words from
`random_u256` with initial seed 42.

**Expectations.** Phase 0 supplies the four first-JAL word fixtures, the two
46-PUSH normal metrics and the short seeded overflow path of four RV64 body
instructions plus eight publisher instructions. Phase 1.4 establishes ten
executed instructions per successful PUSH1. Explicit STOP adds one
instruction. The accepted ABI requires validation before writing, a
status-last publication and deliberate sentinel termination.

### Observed layouts and control transfers

Pinned `asm-rs 0.2.0` assembled each complete symbolic source in one
builder invocation at `0x80000000`. The tests loaded its final bytes directly.
The first exceptional JAL is at `0x80000028` in each layout.

| Layout | Bytes | RV64 words | Normal publisher | Overflow publisher | First exceptional displacement | JAL word | Relocations |
|---|---:|---:|---|---|---:|---|---:|
| 46 PUSH1, EOF | 2,084 | 521 | `0x800007e8` | `0x80000804` | +2012 | `0x7dc0006f` | 138 |
| 46 PUSH1, STOP | 2,088 | 522 | `0x800007ec` | `0x80000808` | +2016 | `0x7e00006f` | 139 |
| 47 PUSH1, EOF | 2,128 | 532 | `0x80000814` | `0x80000830` | +2056 | `0x0090006f` | 141 |
| 47 PUSH1, STOP | 2,132 | 533 | `0x80000818` | `0x80000834` | +2060 | `0x00d0006f` | 142 |

The table gives both publisher labels. The following formulas record the
complete final label addresses and applied relocations compactly. Let
`B = 0x80000000`, `n` be the push count, and `i` range from 0 through
`n - 1`. Each relocation has size 4 and addend 0. Offsets are zero-based
in the final byte stream and the rows repeat in output order for each `i`.

| Label | Final address |
|---|---|
| `guest_push1_i` | `B + 44i` |
| `push1_overflow_i` | `B + 44i + 40` |
| `push1_continue_i` | `B + 44(i + 1)` |
| `guest_stop` (STOP only) | `B + 44n`, or `0x800007e8` / `0x80000814` |
| `normal_exit` | `B + 44n` for EOF, `B + 44n + 4` for STOP |
| `push1_stack_overflow_exit` | `normal_exit + 28` |

| Output offset | Relocation kind | Target label |
|---|---|---|
| `44i + 8` | `RvBranch12` | `push1_overflow_i` |
| `44i + 36` | `RvJal20` | `push1_continue_i` |
| `44i + 40` | `RvJal20` | `push1_stack_overflow_exit` |
| `44n` (STOP only) | `RvJal20` | `normal_exit` |

Phase 1.3's bit-field decoding checks each site's instruction word,
including opcode and branch operands or JAL destination register, sign
extends its immediate, and adds the displacement to the instruction's
own PC. Each site and target is four-byte aligned and inside the emitted
code. All 186 local conditionals branch +32 to their own trampolines.
All 186 success JALs go +8 to their continuations, whose addresses also
match the next fragment, normal publisher or STOP. All 186 exceptional
JALs target the overflow publisher in their layout. Their distances
decrease by 44 per fragment from the first value above. The two STOP
words are `0x0040006f` and jump +4 to the normal publisher. Both publishers
use `jalr zero, -4(t1)` at the end, with `t1 = 0x80100000`. The code ends
well before that jump's destination, the reserved sentinel `0x800ffffc`.
The test checks assembler relocation records separately from these
byte-derived checks and prints all records, labels and decoded targets.

The explicit STOP layouts use the existing one-instruction transfer and
the Phase 1.4 normal and overflow publishers. Their static sizes are 32
bytes smaller than the legacy STOP layout or its 47-PUSH projection. The
legacy supported-program path appends an unreachable eight-word underflow
publisher after overflow. The omission leaves the two reachable publisher
PCs and dynamic counts intact. The spike has no handwritten binary
patches. The harness places an EBREAK only in the reserved sentinel slot
outside the artifact.

### Observed execution

| Initial stack | Layout | Published status / code | Final stack | Live and published `s1` | RV64 body + publisher = total |
|---|---|---|---|---|---:|
| Empty | 46 EOF | NORMAL / 0 | 46 twos | `0x801015c0` | 460 + 7 = 467 |
| Empty | 46 STOP | NORMAL / 0 | 46 twos | `0x801015c0` | 461 + 7 = 468 |
| Empty | 47 EOF | NORMAL / 0 | 47 twos | `0x801015e0` | 470 + 7 = 477 |
| Empty | 47 STOP | NORMAL / 0 | 47 twos | `0x801015e0` | 471 + 7 = 478 |
| 1,024 seeded words | 47 EOF | GUEST_EXCEPTION / 1 | All 1,024 preserved | `0x80109000` | 4 + 8 = 12 |
| 1,024 seeded words | 47 STOP | GUEST_EXCEPTION / 1 | All 1,024 preserved | `0x80109000` | 4 + 8 = 12 |

Each normal run used pre-fetch stops at every trampoline, both publishers
and the sentinel. It reached the normal publisher first, confirming that
it visited none of the trampolines. Each seeded run reached
`0x80000028` in three RV64 instructions, before entering the first PUSH1
value/store path at `0x8000000c`. Resuming with a one-instruction budget
observed arrival at `0x80000830` for EOF and `0x80000834` for STOP. These
were the decoded JAL destinations. The stack pointer remained full, each
initial word matched, and the 32-byte guard immediately above the guest
stack retained all `0xa5` bytes.

The tests checked the publisher words and sampled metadata after the
pointer store, just before and after the status store, and at exit. In
the exception runs the sequence was `(RUNNING, 0, 0x80109000)`,
`(RUNNING, 1, 0x80109000)`, then
`(GUEST_EXCEPTION, 1, 0x80109000)`. A repeated metadata value alone cannot
show a store occurred. The emitted words establish the same-value pointer
store for those runs and the zero exception-code store for normal runs.
All six runs terminated at `0x800ffffc` before fetching the sentinel. The
existing result reader validated the metadata against live `s0` and `s1`.

### Phase 0 comparisons and limits

- **EVM behavior.** The two empty-stack 47-PUSH runs agree with the archived
  Cancun EELS and direct REVM results on successful termination and the
  complete stack of 47 twos. The 46-PUSH observations match the archived
  Ferreth controls. Phase 0's EELS and direct REVM captures cover the
  empty-stack 47-PUSH vectors. The seeded overflow comparison uses the
  Phase 0 short Ferreth overflow observation and ADR-001, with no direct
  seeded EELS or REVM measurement for these vectors.
- **Metrics.** EELS and direct REVM used a 141-gas frame and reported zero
  remaining on both successful inputs. The spike measures completed RV64
  instructions, with the sentinel excluded. It has no frame gas measurement
  or exceptional gas settlement, so this is a bounded status and stack
  comparison.
- **Acceptance.** Legacy accepts both 46-PUSH controls. The four 47-PUSH
  legacy cases still fail before guest execution, with
  `ImmediateOverflow` bounds `-2048..=2047` and attempted displacements
  +2056 or +2060. The spike accepts those four inputs with symbolic
  `RvJal20` references. LF-026 remains open in production.
- **Diagnostics.** EELS terminal EVM PCs are 94 at EOF and 95 with STOP.
  Direct REVM reports 95 for both and result `Stop`. The spike observes
  an RV64 sentinel PC and an ADR-001 status, with code 1 for the seeded
  overflow. These observations use different PC and reporting conventions.

### Reproduction and verification

The verification used Cargo and rustc `1.98.1` on
`aarch64-apple-darwin`, `asm-rs 0.2.0` and `rvemu 0.0.11`. From the
repository root at baseline `d9525c8340c00c050d25c943d28ec93d2847b228`
with the Phase 1.5 changes present, use cached locked dependencies and a
fresh snapshot. This contains rvemu's working-directory writes. The
production commands exclude the Phase 1 spike and run every other
workspace member, including the direct REVM runner's test targets.

```sh
repo="$PWD"
out="$(mktemp -d /tmp/ferreth-phase-1-5.XXXXXX)"
mkdir "$out/checkout"
git archive HEAD | tar -xf - -C "$out/checkout"
cp Cargo.lock "$out/checkout/"
cp -R research/guest-linking/phase-1/. "$out/checkout/research/guest-linking/phase-1/"
cd "$out/checkout"
export CARGO_TARGET_DIR="$out/target"
cargo fmt --all -- --check
cargo test --frozen -p ferreth-linking-spike -- --nocapture --test-threads=1 > "$out/research.log" 2>&1
cargo clippy --frozen -p ferreth-linking-spike --all-targets -- -D warnings
cargo test --frozen --workspace --exclude ferreth-linking-spike --no-fail-fast -- --test-threads=1 > "$out/production.log" 2>&1
cargo test --frozen --workspace --exclude ferreth-linking-spike -- --list > "$out/production-discovery.log" 2>&1
cmp "$repo/Cargo.lock" "$out/checkout/Cargo.lock"
git -C "$repo" diff --exit-code HEAD -- crates research/revm-frame Cargo.toml
git -C "$repo" diff --check
```

| Production workspace | 141 discovered and executed, 137 passed, 4 failed, 0 ignored. Cargo exit 101. |

| Scope and lockfile checks | No production source, production test, direct REVM runner, or root manifest diff. Snapshot and checkout lockfiles matched. |

sentinel. The experiment exercised one host and one executor backend.

### Diff and exit gate

- [Shared test fixture](../tests/support/symbolic_push1.rs) holds the
  relocated Phase 1.4 composer and independent decoder, with optional
  symbolic STOP and checks of the full publisher words.
- [Short tests](../tests/symbolic_push1.rs) use that fixture. The EOF

  relocations, successful runtime behavior, and the two taken overflow
  transfers.
- [Spike manifest](../Cargo.toml) and [workspace lockfile](../../../../Cargo.lock)
  add only a test dependency edge to the existing local
  `ferreth-compiler` package. This lets Cargo run the new tests using the
  public executor, guest ABI helpers and original seeded-word generator.
  The external package inventory and versions are unchanged.
- This report records RF-013 and the [Phase 1 plan](../PLAN.md) records
  the gate. The pre-existing architecture edit retained its original
  Git blob hash `141d4a12172e3152716a5a92e869e05fda95c918`.

**Phase 1.5 exit gate met.** Both seeded 47-PUSH guests reached the
independently verified overflow PCs and preserved the full stack and its
pointer. All four empty-stack layouts published the expected normal
result. RF-013 is covered by the spike tests. A future production
implementation must satisfy the same EOF and STOP regressions through
the production entry points, where the four legacy cases remain red.
The next action is maintainer review of this evidence.

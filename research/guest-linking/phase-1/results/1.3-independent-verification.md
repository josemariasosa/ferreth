# Phase 1.3 — Independent RV64 instruction verification

## Question and scope

Can Ferreth verify the destinations of direct RV64 JAL and conditional
branches from the final bytes emitted by the pinned `asm-rs 0.2.0`?
The gate requires correct signed PC-relative targets for literal and
assembled specimens, including backward JAL and the two instructions in a
relaxed BEQ, and rejection of the specified corruptions. The
[test-local experiment](../tests/independent_verification.rs) uses the
existing `std` and `riscv` features with default features disabled and
assembles at `0x80000000`. It inspects the specimens statically. Ethereum fork
semantics enter only the existing workspace baseline.

## RF-011 — Encoded control transfers can be checked against independent intent

**Source-derived expectations.** JAL uses opcode `0x6f`, with `rd` in
word bits 11:7. Word bits 31, 30:21, 20 and 19:12 supply displacement bits
20, 10:1, 11 and 19:12. A B-type instruction uses opcode `0x63`, with
`funct3` in word bits 14:12. Word bits 31, 30:25, 11:8 and 7 supply
displacement bits 12, 10:5, 4:1 and 11. Both use implicit displacement
bit 0 = 0 and add a sign-extended byte displacement to the instruction's
own PC. For the observed branch pair, BEQ has `funct3=0` and takes the
equal case, while BNE has `funct3=1` and takes the unequal case.
[RISC-V instruction encodings](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv-32-64g.html) ·
[RISC-V control transfers](https://docs.riscv.org/reference/isa/v20240411/unpriv/rv32.html#_control_transfer_instructions)

**Method.** The test reads complete little-endian words from the byte
buffer, checks opcodes, extracts `rd` or `funct3` and the source
registers, sign-extends 21-bit or 13-bit displacements, and uses
`u64::checked_add_signed` to compute actual target PCs. Both site and target
must be four-byte aligned and have four bytes within the given code image.
Literal tests decode specified words directly, independently of assembly
and of the image checks. For assembled tests, the source defines the
intended symbol and test-site PC. Only the expected target address comes
from the final label table, with a separate literal address assertion for
each layout. The actual target calculation uses the site PC and instruction
bytes. Phase 1.3 never reads relocation metadata.
[Phase 1.1 result API](1.1-assembler-api.md) ·
[ADR-001 guest memory layout](../../../../docs/adr/001-evm-guest-state-abi.md)

### Assembled words and final labels

Five programs emitted six checked control transfers. The first three use an
explicit ADDI immediately before the JAL. The forward `jal zero` uses 2052
bytes of padding after the JAL, the backward `jal zero` goes to the first
ADDI, and the forward `jal ra` skips one ADDI.

| Transfer | Emitted word | Site PC | Expected displacement | Observed displacement | Expected label and PC | Observed PC |
| --- | --- | --- | ---: | ---: | --- | --- |
| Forward JAL, `rd=x0` | `0x0090006f` | `0x80000004` | +2056 | +2056 | `destination` `0x8000080c` | `0x8000080c` |
| Backward JAL, `rd=x0` | `0xffdff06f` | `0x80000004` | −4 | −4 | `destination` `0x80000000` | `0x80000000` |
| Forward JAL, `rd=x1` | `0x008000ef` | `0x80000004` | +8 | +8 | `destination` `0x8000000c` | `0x8000000c` |
| Nearby BEQ, `funct3=0` | `0x00628463` | `0x80000000` | +8 | +8 | `destination` `0x80000008` | `0x80000008` |
| Relaxed BNE, `funct3=1` | `0x00629463` | `0x80000000` | +8 | +8 | `fallthrough` `0x80000008` | `0x80000008` |
| Inserted JAL, `rd=x0` | `0x3880106f` | `0x80000004` | +5000 | +5000 | `destination` `0x8000138c` | `0x8000138c` |

Both conditional programs assemble `beq t0, t1, destination` followed by
`fallthrough`, then either 1 or 1249 NOPs, and a final NOP at
`destination`. The nearby program places its fallthrough at
`0x80000004`. In the distant program, both the original BEQ and emitted
BNE compare `x5` and `x6`. For unequal inputs (original BEQ false), the
decoded BNE takes the +8 path to the final fallthrough label and skips
the JAL at `0x80000004`. For equal inputs (original BEQ true), BNE would
advance to the JAL, whose +5000 displacement is relative to its own PC
and reaches the final distant label. These paths follow from the decoded
condition, registers and targets together with ISA semantics.

### Negative fixtures

The main mutation fixture has four words at `0x80000000` and an exclusive
end at `0x80000010`. The original `0x0080006f` passes with target
`0x80000008` and `rd=x0`. The same intended PC and register are used for
each mutation.

| Case | Changed word or input | Observed result |
| --- | --- | --- |
| Valid encoding, wrong destination | `0x00c0006f` | +12 to aligned and in-bounds `0x8000000c`, rejected as `WrongTarget` |
| Unexpected destination register | `0x008000ef` | +8 to `0x80000008` with `rd=x1`, rejected as `WrongRd` |
| Outside executable bytes | `0x0100006f` | +16 to the exclusive end `0x80000010`, rejected as `TargetBounds` |
| Target misalignment | `0x0060006f` | +6 to `0x80000006`, rejected as `TargetAlignment` |
| Unexpected JAL opcode | `0x00800013` | Rejected as `Opcode(0x13)` |
| Unexpected branch condition | `0x00629463` where BEQ is expected | BNE `funct3=1`, rejected as `WrongBranchFields` |
| Unexpected branch opcode | `0x0080006f` where BEQ is expected | Rejected as `Opcode(0x6f)` |
| Invalid site | PC `0x80000002` or 3 bytes available at site | `SiteAlignment` and `SiteBounds`, respectively |
| Partial target word | 11-byte image with target at byte 8 | Rejected as `TargetBounds` |
| LF-027 sign bit cleared | `0x7fdff06f` at `0x80000004` | +1,048,572 to `0x80100000`, rejected as `TargetBounds` |
| Address underflow and overflow | −4 at PC 0, +8 at `0xfffffffffffffffc` | Both rejected as `AddressOverflow` |

The LF-027 fixture holds the intended target at `0x80000000`. Restoring
instruction bit 31 gives `0xffdff06f`, which verifies with displacement
−4 at the same site. This reproduces the encoding discrepancy using
literal words. [LF-027 architecture finding](../../../../docs/research/ferreth-linking-architecture.md#additional-findings-from-independent-review)

### Implications, regression status, and limits

RF-011 establishes a test-local mechanism for these direct transfers.
Verification needs a known final site PC and a separately supplied
intended destination. The experiment exercises exact target matching,
expected register and condition checks, range-safe target arithmetic,
alignment and full-word bounds. The named tests above implement research
regressions for the literal range edges, the LF-027 backward JAL, both
paths of the relaxed BEQ, and the corruptions. Future production acceptance
needs equivalent regressions at actual guest reference sites. LF-026 and
LF-027 remain open in production.

The tested layouts have known instruction sites and a contiguous byte
image inside the guest code reservation. The helper checks individual
addresses against that image. Whole-guest size and exit-slot validation,
code versus data classification, discovery of every reference site,
arbitrary relaxation patterns, other branch conditions, JALR, compressed
instructions and dynamic behavior are outside the evidence. The
positive JAL ISA endpoint is only halfword aligned and the negative
endpoint fixture uses a site outside the guest code reservation. Both
are decoder fixtures. None of the Phase 1.3 specimens ran in an emulator.

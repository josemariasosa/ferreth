# Phase 1.1 — Assembler result API

## Research question

What final bytes, label addresses, and applied relocation details does
`asm-rs 0.2.0` expose for a forward symbolic RV64 JAL at a nonzero origin?
The gate requires source evidence for the address conventions and a reproducible
specimen that matches independently calculated words, addresses, and displacement.
This is an assembler API experiment. Ethereum fork semantics do not enter the
specimen.

### Relocation records and address conventions

The public low-level `asm_rs::encoder::Relocation` represents an unresolved
reference (`src/encoder.rs:322–341`). The builder result exposes only the
applied record, re-exported as `asm_rs::AppliedRelocation`
(`src/linker.rs:192–203`).

```rust
pub struct Relocation {
    pub offset: usize,
    pub size: u8,
    pub label: alloc::rc::Rc<str>,
    pub kind: RelocKind,
    pub addend: i64,
    pub trailing_bytes: u8,
}

pub struct AppliedRelocation {
    pub offset: usize,
    pub size: u8,
    pub label: String,
    pub kind: RelocKind,
    pub addend: i64,
}
```

`RelocKind` is a public enum and `RvJal20` is its JAL variant under the
`riscv` feature (`src/encoder.rs:242,302–304`). The private and crate-private
implementation relevant to this specimen works as follows.

- The two-operand symbolic JAL encoder creates a four-byte placeholder with
  an instruction-relative relocation offset of zero. A plain label
  contributes an addend of zero.
  (`src/lib.rs:95–96`, `src/riscv.rs:498–500,2004–2021`,
  `src/encoder.rs:371–375`.)
- Layout starts at the virtual base. The final label table uses those absolute
  layout addresses. After patching, the applied record reports the zero-based
  output byte offset, calculated as the length already emitted plus the
  instruction-relative relocation offset.
  (`src/linker.rs:657–664,722–741,865–872`.)
- The patcher computes the absolute site from the fragment address plus the
  instruction-relative offset. For `RvJal20`, it calculates the byte
  displacement as target address minus that site plus the addend and writes
  the J-type immediate into the final little-endian word. The applied record
  carries the site offset and input addend. The instruction PC, resolved
  target address, and calculated displacement have no fields in that record.
  (`src/linker.rs:877–887,1353–1376`.)

## Specimen and observed result

Base address `0x80000000`, architecture `Arch::Rv64`.

```asm
entry:
    addi t0, zero, 42
    jal zero, destination
    addi t0, zero, 99

destination:
    addi t1, zero, 7
```

| Instruction address | Expected word | Observed word |
| --- | --- | --- |
| `0x80000000` | `0x02a00293` | `0x02a00293` |
| `0x80000004` | `0x0080006f` | `0x0080006f` |
| `0x80000008` | `0x06300293` | `0x06300293` |
| `0x8000000c` | `0x00700313` | `0x00700313` |

The 16-byte output matches the size hypothesis. The full label table is
`destination = 0x8000000c` and `entry = 0x80000000`, in that order.
The sole relocation points to bytes `[4..8]`, which are `6f 00 80 00`.
Adding output offset 4 to the base gives JAL PC `0x80000004`.
The target minus this PC is `+8` bytes. The displacement check uses the
reported addresses and the test compares the emitted word against the
independent expectation.

The test output follows with trailing listing padding removed.

`assemble_at` matched the builder at `0x80000000`. `assemble` matched a
separate builder run at its default base of zero. The two origins also
produced identical bytes for this specimen, consistent with moving the
local target and JAL PC by the same amount.

## Regression and limits

[LF-030](../../ferreth-linking-architecture.md#additional-findings-from-independent-review)
tracks the pinned assembler capability. The
[experiment test](../tests/assembler_api.rs) guards the four-word specimen
at `0x80000000`, including the label values, applied relocation, target
arithmetic, and convenience API equality at equivalent origins. This is
research coverage for a single local forward reference. Ferreth's
production target validation remains a separate requirement, since the
reported relocation describes the reference the assembler patched and
Ferreth still needs to establish the intended destination.

The experiment covers assembly only. Backward references, range and
alignment boundaries, duplicate and undefined symbols, external label
behavior, and layout changes from relaxation remain open for later
authorized probes. LF-026 and LF-027 remain open.

## Exit gate

Met for Phase 1.1. The pinned public API reproduced the expected bytes
and established the absolute label and output-relative relocation
conventions for the specimen. The maintainer can review the evidence
before authorizing Phase 1.2.

# Phase 1.2 — Symbolic control flow

## Scope and method

The [experiment](../tests/symbolic_control_flow.rs) uses `Arch::Rv64` at
`0x80000000` with the existing `asm-rs = "=0.2.0"` pin, default features
disabled, and `std` and `riscv` enabled. The lockfile checksum for the crate
is `b43cd6bd0e5c09388248d6619d4f7e79b2f4f86b4aecf1f830430e40acee1455`.
The specimens produce bytes and metadata for inspection. They never execute.
Ethereum fork semantics enter only the existing workspace regression suite.

The expected words are literal fixtures derived from the ISA instruction
formats. JAL adds a signed byte displacement to its own PC, with bit 0 implicit.
The J-type word stores displacement bits `[20|10:1|11|19:12]` in bits
`[31:12]`. The representable even displacement interval is
−1,048,576 through +1,048,574. Four-byte-aligned sites and targets narrow the
positive edge to +1,048,572. Ferreth also reserves an exit slot in a 1-MiB code
region. The MiB-scale vectors exercise assembler range handling in isolation.
[RISC-V instruction formats](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv-32-64g.html) ·
[RISC-V JAL and IALIGN](https://docs.riscv.org/reference/isa/v20240411/unpriv/rv32.html#_unconditional_jumps) ·
[ADR-001 memory layout](../../../../docs/adr/001-evm-guest-state-abi.md)

The tests read the actual site and destination labels from the final result and
compare their addresses and emitted words to the fixtures. Where assembly
fails and returns no result table, a paired control replaces the JAL with
a same-width `addi zero, zero, 0`. The reported error displacement is checked
against the observed control addresses.

## RF-008 — Symbolic JAL displacement and range

`symbolic_jal_forward` assembles one `addi zero, zero, 0` before the JAL and
`displacement / 4 − 1` copies between the JAL and `destination`. A final
`addi` marks the target. The +8 displacement repeats the Phase 1.1 check
with different surrounding instructions. `symbolic_jal_backward` defines
`destination` first, with `distance / 4` copies of the same `addi` before
the JAL. `symbolic_jal_signed_boundaries` uses a single `.space` directive
per specimen to exercise MiB-scale layouts with a few source lines.

Each accepted case returned one applied relocation of kind `RvJal20`, size
4, label `destination`, and addend 0. The table includes the observed
output-relative offset. The word column gives both the expected and observed
value, which matched in every row.


**Source explanation.** In the pinned crate, the symbolic two-operand JAL
path emits a fixed four-byte instruction and attaches `RvJal20`
(`src/riscv.rs:2004–2021`). The patcher checks
`[-(1 << 20), 1 << 20)`, then requires an even displacement before encoding
it (`src/linker.rs:1353–1376`). Its displayed `max=±1048574`
suggests a symmetric interval, but the accepted −1,048,576 specimen
demonstrates the actual lower edge. Numeric JAL goes through the signed
12-bit immediate reader (`src/riscv.rs:439,2023`), which accounts for
the four production failures. Their diagnostics below are from the
workspace run.

**Implication and regression status.** The +2056 and −4 fixtures are passing
assembler regressions for [LF-026 and LF-027](../../ferreth-linking-architecture.md#additional-findings-from-independent-review).
The −4 word has bit 31 set. The legacy helper's `0x7fdff06f` is the
observed encoding for the positive four-byte-aligned maximum. The production
47-PUSH EOF and STOP cases remain open, including their taken overflow paths.
Any retained handwritten encoder requires signed edge and rejection coverage.

## RF-009 — Alignment and named-symbol diagnostics

`symbolic_jal_alignment` leaves the JAL site at `0x80000000` and controls
the destination with no padding, `.byte 0`, or `.byte 0, 0`.
The target instruction is the same four-byte `addi` in each specimen.

| Padding before target | Destination | Expected | Observed |
| --- | --- | --- | --- |
| None | `0x80000004` | Accept +4 | `0x0040006f`, 8 output bytes |
| `.byte 0` | `0x80000005` in control | Reject odd +5 | `MisalignedBranchTarget` with required alignment 2 |
| `.byte 0, 0` | `0x80000006` | Accept encodable +6 | `0x0060006f`, 10 output bytes |

Each accepted alignment case applied one
`{ offset: 0, size: 4, label: "destination", kind: RvJal20, addend: 0 }`.
The odd diagnostic was:

```text
MisalignedBranchTarget { label: "destination", disp: 5, alignment: 2, span: Span { line: 2, col: 1, offset: 6, len: 3 } }
2:1: branch target 'destination' is not 2-byte aligned (displacement=5)
```

`named_symbol_errors` tests a lone `jal zero, destination` and a source
with two `destination:` definitions separated by one `addi`. As expected,
the undefined reference passed `emit` but failed `finish`, and the duplicate
failed `emit`. Valid forward and backward named references succeeded in
the JAL tests above. These diagnostics apply to ordinary named symbols.

```text
finish: UndefinedLabel { label: "destination", span: Span { line: 0, col: 0, offset: 0, len: 0 } }
0:0: undefined label 'destination'
emit: DuplicateLabel { label: "destination", span: Span { line: 3, col: 1, offset: 32, len: 12 }, first_span: Span { line: 1, col: 1, offset: 0, len: 12 } }
3:1: duplicate label 'destination' (first defined at 1:1)
```

**Source explanation.** The parser accepts `.byte` and `.space`
(`src/parser.rs:209,231`). The JAL relocation checks displacement
granularity (`src/linker.rs:126,1368`). Named label insertion retains the
first span for the duplicate diagnostic (`src/linker.rs:376–399`), while
failed named lookup yields a zero span (`src/linker.rs:1534–1542`).

**Implication and regression status.** Assembler acceptance establishes
JAL immediate encodability. The passing +6 specimen shows that Ferreth
must also check four-byte alignment of final instruction addresses.
Assembler regressions cover the +4, +5, and +6 cases and both symbol
errors. Any future production validation needs a case that rejects an
assembler-accepted halfword-aligned destination. Undefined named labels
yield limited source diagnostics, and the API returns applied relocations
only for successful assembly.

## RF-010 — Conditional branch relaxation changes layout

`symbolic_conditional_branch_relaxation` assembles two programs of the
same shape. Both start with `site: beq t0, t1, destination`, then label the
`fallthrough` before padding with `addi zero, zero, 0` and end with a
labeled destination `addi`. The padding differs only in length. The
predicted short form was a single BEQ, and the predicted long form was an
inverted condition plus JAL. Both predictions matched the emitted words
and final layout.

| Case | Padding instructions | Final bytes | Site | Fallthrough | Destination | Control-flow instructions at site |
| --- | ---: | ---: | --- | --- | --- | ---: |
| Nearby | 1 | 12 | `0x80000000` | `0x80000004` | `0x80000008` | 1 |
| Distant | 1249 | 5008 | `0x80000000` | `0x80000008` | `0x8000138c` | 2 |

| Case | PC | Expected = observed word | Instruction and destination |
| --- | --- | --- | --- |
| Nearby | `0x80000000` | `0x00628463` | `beq t0, t1, +8` to `0x80000008` |
| Distant | `0x80000000` | `0x00629463` | `bne t0, t1, +8` to `0x80000008` |
| Distant | `0x80000004` | `0x3880106f` | `jal zero, +5000` to `0x8000138c` |

```text
Nearby:  [AppliedRelocation { offset: 0, size: 4, label: "destination", kind: RvBranch12, addend: 0 }]
Distant: [AppliedRelocation { offset: 4, size: 4, label: "destination", kind: RvJal20, addend: 0 }]
```

For unequal registers the long form skips the JAL and reaches
`fallthrough`. For equal registers it executes the JAL, whose displacement
starts at the second word. The original BEQ site is 5004 bytes from the
target. A one-word-per-source-instruction count would put the fallthrough
and destination four bytes early in the distant case. The final label table
records both shifts. The long form's applied relocation describes the
JAL, with no corresponding record for the fixed BNE skip.

**Source explanation.** The pinned branch encoder constructs the short
B-type form and the long inverted branch plus JAL form
(`src/riscv.rs:1830–1873`). The linker tests short-form reach during layout
(`src/linker.rs:530–552`). The long form still depends on JAL reach.
This experiment checks one nearby and one distant forward BEQ. It does
not establish behavior for all conditional mnemonics, layouts, or relaxation
interactions.

**Implication and regression status.** The test checks both sequences,
relocations, and final addresses. Any later target verification needs the
final label addresses, the location of the actual relocated instruction,
and an independent check of the encoded path. The applied relocation
reports the patch that was made. The intended destination remains a
separate input to that verification.

## Exit gate

Met for Phase 1.2. The pinned assembler resolved local named JALs in both
directions, matched the signed boundary encodings, rejected the tested
unencodable offsets, classified symbol errors, and exposed the layout changes
from conditional relaxation. The observed limits require Ferreth to enforce
its own four-byte alignment and validate intended targets from the final
layout. Production behavior remains at the known RED checkpoint. The
maintainer can review these results before authorizing Phase 1.3.

# Phase 1.7 — Symbolic guest composition architecture recommendation

**Status.** Phase 1.7 decision package complete. Architectural approval and authorization for Phase 2 are pending. Source inspected at `1732e0325adfba1d943e1345f4a0e7307cdd8fa7`. [Phase 1 plan](../PLAN.md)

## RF-015 — Use one symbolic composer with independently checked publisher references

Recommend one RV64 guest composer backed by the existing frozen `asm-rs 0.2.0` resolution. Emit one readable symbolic source, assemble it once at `ENTRY_PC`, and validate the final words before constructing `CompiledRv64Program`. Keep a compile-time record of each external transfer's site and intended publisher role. Choose the publisher inventory in the composer and implement publication once. Retain the public compile, execute and fragment entry points and the standalone pointer-ABI arithmetic path.

The recommendation addresses both demonstrated JAL defects while removing the duplicated ownership of publisher generation and the coupling between manual byte patches and textual rewrites. It depends on a bounded instruction vocabulary, a final label map and an independent verifier. The pinned assembler already supplies the required APIs. Production currently declares `0.2.0` with Cargo's compatible-version syntax and resolves exactly `0.2.0` in the lockfile. Use the existing feature set and frozen resolution for Phase 2, with any future version or feature change subject to compatibility review. **Source-derived resource risk.** The pinned builder defaults to 100,000 labels, 1,000,000 statements, 16 MiB of output and 64 MiB per source input (`asm-rs-0.2.0/src/assembler.rs`, `ResourceLimits` and `Assembler::emit`). A dense guest can hit the label cap within Ferreth's code reservation. For example, 52,424 current 20-byte POP bodies plus the 92-byte mixed publisher tail fill the executable interval, and two labels per POP would already exceed the default. Phase 2 must check the proposed symbol density and source bounds, and justify any finite assembler limits needed for valid guest layouts. The large-layout gates are proposed, with performance and peak memory still unmeasured.

## B. Alternatives

| Criterion | 1. Manual linker with targeted fixes | 2. Shared checked relocation primitives | 3. One symbolic composer |
|---|---|---|---|
| Correctness | Repair signed encoding in both places and change the final assembly strategy so long JALs avoid numeric parsing. Each path still chooses its sites and publishers. | One checked signed encoder and decoder can fix LF-027 and enforce bounds. LF-026 still needs compatible assembly rendering at each path or a common renderer. | Symbolic JALs handle LF-026, and retirement of the two encoders eliminates their LF-027 behavior. Ferreth must independently check semantic routing and final layout. |
| Complexity and maintenance | Smallest immediate patch. Three layout paths and two publisher implementations remain. | Moderate extraction and narrower low-level maintenance. A patch layer, source anchors and caller-owned composition still require coordination unless also consolidated. | Largest initial cutover. One placement/publication owner and one source of bytes remove permanent patching and string reconstruction. |
| ABI and artifacts | Easiest to preserve historic layout. A valid long display may still need symbolic text. | Usually preserves bytes and layout. API convergence is separate. | ABI and short artifact parity are supported by the spike. Guest text changes, and unifying isolated arithmetic may add an unused publisher. |
| Future metering | Every composition path must accommodate additional exits. Publication changes have multiple owners. | Shared patches help route an added target, but settlement can still drift across publisher owners. | An additional semantic role and one publisher owner accommodate routing and later settlement. Metering order and ABI remain separate decisions. |
| Dependency risk | Existing numeric parser behavior needs a workaround. Independent manual encoding remains Ferreth's responsibility. | Less dependence on symbolic layout if Ferreth calculates placement. A second representation and its long-range display still need validation. | Uses the existing crate with greater reliance on final label and relaxation behavior. Keep frozen builds, a small adapter, and negative fixtures. Review upgrades using the recorded corpus. |
| Verification burden | Independent checks and old/new parity across all three paths. | Add primitive edge tests and retain per-path routing and ABI checks. | Add manifest coverage and publisher-role checks with final-byte decoding. Use old/new execution parity during migration, then maintain one composition contract and all public-entry regressions. |

Option 1 is credible for a narrow production repair if consolidation is rejected. Option 2 is the fallback if final symbolic layout or diagnostics prove unsuitable at the production boundary. Its minimum credible version includes corrected signed encoding, an independent decoder, and a long-range-safe readable representation. Prefer option 3 because the current subset fits one assembler pass with fixed-width local sequences, and its ownership changes remove more failure modes than a shared patch helper. This is an architectural inference from the evidence and traced code. ## D. Design decisions proposed for approval

1. **Symbolic external transfers.** A named `jal zero, publisher` is sufficient for normal STOP and stack exceptions. Every publisher is defined in the same source. With the reserved sentinel slot excluded, all aligned internal instruction pairs fit signed JAL reach. Preserve nearby stack-check branches to local trampolines and use symbolic JAL for the distance to the publisher. The current model requires no unresolved object format, general linker or new IR.
2. **Minimal reference manifest.** Record a site label and a semantic publisher role (normal, stack overflow, stack underflow) at emission. Derive the assembler operand from that role through the composer's publisher map. The two DUP1 sites must declare different roles even when both destinations are valid labels. The verifier resolves the expected role independently of the assembler's relocation record and checks `jal x0` from the bytes. Reject duplicate or missing sites and undeclared external transfers. Keep local expectations with generators (site, local destination role and relevant instruction fields), and check local targets and inventory without building a general relocation representation. The manifest is compile-time internal. Directed semantic fixtures must supply their own expected outcomes to catch a generator that declares the wrong role consistently.
3. **Local uniqueness.** Assign deterministic ordinals in lowered instruction order. Give each occurrence a disjoint prefix and use fixed role names for its entry, sites, trampolines, continuations and arithmetic leaf/return. Keep publisher names in a reserved namespace. Generate definitions and references directly from those names. Duplicate symbol definitions fail. Distinct names may share a PC only where the layout intentionally aliases a continuation with the next entry or the normal publisher.
4. **Publisher PCs.** Look up declared publisher start labels in the final `AssemblyResult` at `ENTRY_PC`. Check required labels, full-word bounds, alignment, distinct ordered publisher starts at the declared body/publisher boundaries, and their expected entry and publication sequence against final words. Obtain static publisher lengths from validated final ranges. Preserve two publishers for PUSH1-only EOF (including empty input), three for mixed or explicit STOP, and the normal-first, overflow-second convention for PUSH1. Use ordinary mixed inventory for isolated ADD/SUB after review of LF-028's observed static change from 232 to 264 bytes (58 to 66 words). With the same wrapper, the unused overflow publisher shifts the underflow PC from `0x800000c8` to `0x800000e8`. Normal remains at `0x800000ac`. Both exception publishers are eight words in the current ABI, so the existing single exceptional count remains well-defined.
5. **Relaxation and execution bound.** Calculate downstream sites, ranges, static size and budget after final assembly. Require one-word local checks for Phase 2 and reject an unexpected expansion. If later supported, a relaxed check must verify the inverted condition and skip, the inserted JAL from its own PC, and both successors. For the current forward fragment progression, single call to each occurrence's leaf, return to its own continuation path, and single terminal publisher, no word executes twice. Keep `final_bytes.len()/4` as the shared total limit and subtract the observed body count for the publisher run. Any future path that revisits code needs a fresh bound. Preserve pre-fetch exit detection and successful instruction counting.
6. **Entry-point convergence.** Keep `compile_push1_program` as an immediate adapter to the same lowered composition used for equivalent bytecode. Preserve bytecode/sequence equality. Keep `execute_guest_add/sub` and seeded variants as adapters to single-op bytecode, as POP and DUP1 already do. Public fragment generation and translation retain the unlinked artifact contract. Compilation stays independent of initial stack and execution.
7. **Future OOG.** A wrapper must be able to request another semantic exit without modifying the placement algorithm or imposing a fixed count of exceptional sites. A later approved charge check can branch to an OOG trampoline before opcode effects, and the shared publisher emitter can own the reviewed exceptional settlement protocol. Any gas fields, codes, charging precedence, instruction support or future change to static publisher metrics require separate review. The observed Cancun reference difference for low-budget ADD prevents treating proposed charge-first diagnostic precedence as settled. [Proposed ADR-002](../../../../docs/adr/002-cancun-evm-gas-metering.md) · [Reference discrepancy](../../ferreth-linking-architecture.md#6-gas-metering-as-an-architectural-stress-test)
8. **Identity and equivalence.** Protect standalone ADD/SUB leaf bytes and hashes, including each embedded copy, and preserve the pointer calling convention and core benchmark scope. Keep equivalent PUSH1 public inputs equal to one another and keep linked display reassemblable to the exact loaded bytes. For guest artifacts across versions require ABI and semantic equivalence. Use historical byte, publisher PC, static size and split count comparisons to detect and explain every migration delta. Exact historical guest text is outside the compatibility contract proposed here. Preserve the short layouts by default. Review any consumer requirement for exact guest bytes, text or metadata before changing a relied-on convention. [Maintainer direction](../../ferreth-linking-architecture.md#maintainer-direction-2026-11-19) · [ADR-001 benchmarks](../../../../docs/adr/001-evm-guest-state-abi.md#8-benchmark-compatibility)
9. **Independent verification.** Read final little-endian words and check complete aligned sites and targets, opcode, JAL destination register, branch condition and operands, signed displacement arithmetic and exact intended destination. For this contiguous instruction-only image, compare the inventory of direct transfers with the declared sites, and allow only the expected indirect returns and publisher exits. Verify each arithmetic call, its `PC+4` return anchor and exact leaf return, and the publishers' ABI address derivation, status-last stores and sentinel transfer. Check body fallthrough reaches the intended boundary, the image ends at or before `EXIT_PC`, and only publisher exits target the sentinel. Runtime ABI tests still verify reached PCs, actual register and stack effects, publication checkpoints, guard words and host-error separation. Relocation records and source round-trip equality can support diagnostics and reproducibility.
